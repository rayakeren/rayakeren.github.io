Bedroom lighting rig

LITTLE MAYOR · 2026

The whole game takes place on a kid's bedroom floor, so the light has to feel like a real room at different times of day.

  • Baked lighting with a skylight area fill and a warm volume profile
  • Day/night ambience pass, with menu and gameplay scenes rebaked to match
  • Kept cheap enough for the WebGL demo build
URPBaked GIPost-processing

Cel-shaded clay puffs

LITTLE MAYOR · CUSTOM SHADER

Placing or demolishing a building throws out chunky "clay" dust. Soft alpha particles sorted badly when they stacked, so I wrote a shader that treats them as solid meshes instead.

  • Alpha-clipped and depth-writing, so overlapping chunks sort per pixel
  • Light quantised into flat bands to match the toy look
  • Baked ambient (SH) mixed in so puffs sit in the room's light
  • Driven by a pooled VFX system to avoid spawn spikes

Toon shading and VFX for a whole game

TORCH IT! · SHADER GRAPH

A caveman carries the last flame home, so the world needed to read like a picture book. I built one unlit toon shader for the whole game, lit and graded each level by hand, and made all the VFX.

N · −L→max 0→floor into bands→max shadow→× texture
  • Light quantised into flat bands, with a shadow-brightness floor so dark sides keep their colour
  • Unlit, so it stays cheap with lots of foliage on screen
  • Lighting and post-processing pass for all four levels
  • All VFX: cartoon fire built from custom mesh particles and an additive material, wind gusts, lightning strikes, walking and landing dust

A timing game that fights back

PRESS SPACE AT THIS EXACT TIME · SOLO JAM

My first solo game jam, theme "Space and Time". Press the right key exactly at 0.00 on a notebook page, while Bob, a smug stick-figure host, does his best to throw you off.

Servers and pipelines behind the games. Nobody sees this part, so here's how it works.

.NET 8 · FastAPI · PostgreSQL · Docker

Authoritative multiplayer server

PROJECT LUDO · IN DEVELOPMENT

A Ludo game with character abilities and special tiles, played online. I wrote the backend.

  • The server rolls the dice, validates every move and resolves captures, coins and tile effects
  • Guest accounts with signed JWT tokens
  • Party and queue matchmaking for groups of 1 to 4
  • Client and server share one rules source, so they can't drift apart
  • Containerised deploy with a reverse proxy and load-test scripts
C#ASP.NET CoreDockerJWT

Playtest telemetry pipeline

WING-IT · PLAYTESTING

We needed to know where players died and quit, not just what they told us.

  • Unity side: a buffered telemetry service with consent, anonymous IDs, and context on damage, deaths and level entry
  • Server side: a FastAPI endpoint that batches events into PostgreSQL as JSONB
  • Output: playtest reports generated from the data
